# Workflow

Purpose: 确定为什么做、为谁做、解决什么问题、如何衡量，并把可验证的产品意图交给设计。

## Stages

### 1. INTAKE

明确决策、用户、业务目标、边界、项目类型和最大未知量。

Primary output: `product-brief`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 2. DISCOVERY

将需求表述改写为问题假设，收集行为与用户证据并寻找反证。

Primary output: `discovery-evidence`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 3. STRATEGY

定义 ICP、JTBD、替代方案、定位、战略楔子、差异化和产品论点。

Primary output: `product-strategy`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 4. PRIORITIZATION

优先排列问题/机会而非功能；根据场景选择评分框架。

Primary output: `prioritized-opportunities`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 5. DEFINITION

把证据、战略、范围、用户旅程、边界和指标固化为 PRD。

Primary output: `prd`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 6. PLANNING

把目标分解为 Outcome → Opportunity → Initiative → Experiment/Feature。

Primary output: `outcome-roadmap`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 7. VALIDATION

执行 pre-mortem、反方审查和关键假设检查，维护风险登记。

Primary output: `risk-register`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 8. MEASUREMENT

建立 North Star、输入指标、护栏指标及 Metric → Hypothesis → Decision。

Primary output: `measurement-plan`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

### 9. HANDOFF

检查全套产品制品、追踪关系和未决问题，通过 pm-ready。

Primary output: `pm-ready`.

Exit only when the output has explicit acceptance criteria, registered evidence and no hidden critical blocker.

## Regression and re-entry

- New contradictory evidence: return to the earliest stage that owns the invalid assumption.
- Downstream implementation constraint: distinguish a true constraint from convenience; update the owning artifact and traceability.
- Critical risk: block progression unless mitigated, explicitly accepted or formally waived.
- Small bounded request: execute only affected stages while preserving upstream/downstream checks.
