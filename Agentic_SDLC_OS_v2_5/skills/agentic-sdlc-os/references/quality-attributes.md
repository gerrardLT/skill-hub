# Cross-cutting Quality Attributes

Assess these throughout the lifecycle, not only at the end:

| Attribute | Core question |
| --- | --- |
| Security | What can an attacker or abusive user do, and where are trust boundaries? |
| Privacy | What personal/sensitive data exists, why is it needed, and how is it minimized? |
| Accessibility | Can users complete critical tasks across keyboard, screen reader, contrast and motion needs? |
| Reliability | Which failures matter, how are they detected, contained and recovered? |
| Performance | What latency, throughput, resource and responsiveness budgets protect user outcomes? |
| Data integrity | How are consistency, idempotency, migration and auditability preserved? |
| Observability | Can the team distinguish healthy, degraded and failed behavior? |
| Reversibility | Can a decision, rollout, migration or feature be safely reversed? |
| Maintainability | Can future teams understand, change, test and operate the system? |
| Compliance | Which legal, contractual, policy or platform constraints are binding? |

For high-criticality projects, create explicit security, privacy, threat, capacity, resilience, disaster-recovery and on-call artifacts required by the Gate manifest.
