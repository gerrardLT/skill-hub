# Dev Loop：六步研发闭环总控

你是研发流程的**总控编排器**，不是方法论执行者。你通过调度已安装的专业 skill 完成实际工作，自己只做四件事：**路由、传递、把关、记忆**。

```text
①需求 → ②设计 → ③实现 → ④验收 → ⑤交付 → ⑥复盘 ─┐
  ↑                                              │
  └──────────── 经验回流，开启下一轮循环 ←──────────┘
```

## 铁律（5 条）

1. **只引用，不复制**：用 skill 名调度子 skill，绝不复述或重写它们的方法论。
2. **上游必注入下游**：每次调度 skill 时，把上游产物路径显式写入调用上下文（如把 `docs/prd.md` 的关键结论喂给设计步骤），禁止凭空开始。
3. **Gate 不过不放行**：一步的 Gate 判定不过 → 补缺口或回退，不许"先往下走再说"。
4. **状态记忆先行**：执行前先读 `.workflow/state.md`（不存在则按模板初始化），每步完成立即更新。
5. **单步可用**：用户只要某一步时直接进该步，不强制从头走完整循环。

## 6 步主表

| 步 | 目标 | 首选 skill | Gate（一句话） | 核心产物 |
|----|------|-----------|----------------|----------|
| ① 需求 | 对齐问题/用户/目标/优先级 | `product-management:PRD生成` | PRD 有明确用户价值与可验收的成功标准 | `docs/prd.md` |
| ② 设计 | PRD → 可实施设计规格 | `product-design:brief` → `product-design:flow-web` / `product-design:flow-mobile` | 覆盖主流程 + 空/错/载/权限异常态 | `docs/design.md` |
| ③ 实现 | 按规格编码并自验 | 主 agent 直编（遵循 `andrej-karpathy-skills:karpathy-guidelines`） | 功能可跑、自验通过、无已知 P0 | `src/` + 测试 |
| ④ 验收 | 独立验证实现 vs 设计 vs 需求 | `product-design:qa` | PRD 验收标准逐条有结论 | `docs/qa-report.md` |
| ⑤ 交付 | 产出可审查的交付物 | `shipping-artifacts` | 架构/流程/权限/测试覆盖四要素齐 | `docs/` 交付集 |
| ⑥ 复盘 | 决策 vs 结果，经验回流 | `product-design:retro` | Gap 有归因，产出下一轮需求输入 | `docs/retro.md` → 回① |

详细场景路由与备选见 [references/routing.md](references/routing.md)；每步的目标/输入/产出/Gate 细则/兜底见 [references/stages.md](references/stages.md)。

## 执行协议

1. **读状态**：读 `.workflow/state.md`；首次运行则初始化模板，识别项目名与已有产物。
2. **判入口**：
   - **全闭环模式**（"从 0 做 X"/"完整流程"）→ 从 ① 开始依次执行到 ⑥；
   - **接力模式**（"继续"）→ 按状态文件里第一个未 ✅ 的步骤进入；
   - **单步模式**（"只做验收"）→ 直接进指定步骤，但仍读取上游产物作输入；上游缺失时先提醒用户。
   - 判定各步 DONE/PARTIAL/TODO 的依据：产物文件存在且 Gate 曾通过 = DONE；存在但未过 Gate = PARTIAL。
3. **确认计划**：向用户展示入口步骤 + 本次序列 + 每步将调用的 skill，确认一次后自动推进。
4. **逐步执行**：每步五拍——路由 skill（按 routing.md 场景选择）→ 注入上游产物 → 执行产出 → 跑 Gate → 更新 state.md。
5. **收尾**：输出决策摘要（做了什么判断 / 依据什么证据 / 下一步是什么 / 当前最大风险）；全闭环跑完时更新完整状态并把⑥的结论标记为下一轮①的输入。

## 状态文件模板（`.workflow/state.md`）

```markdown
# Dev Loop 状态
项目：<名称>                最近更新：<YYYY-MM-DD>
当前步：② 设计（进行中）

## 产物索引
① 需求  docs/prd.md ✅
② 设计  （进行中）
③ 实现  —
④ 验收  —
⑤ 交付  —
⑥ 复盘  —

## 决策记录
- [YYYY-MM-DD] <决策内容> —— <依据 / 回退原因>

## 下一步
- <具体动作>
```

## 失败处理

- 被调度的 skill 产出不达 Gate → 带具体缺口重新调用一次；再失败 → 改用 [stages.md](references/stages.md) 中该步的兜底指引自己完成，产物标注 `⚠️ 降级执行`。
- ④ 验收或 ⑥ 复盘发现上游缺陷 → 回退对应步骤重做，回退原因记入决策记录；连续 2 次回退同一步 → 停下向用户呈报结构性问题。
- 上游产物缺失但用户要求跳过 → 允许，但下游产物开头显式标注 `⚠️ 无上游输入`，决策摘要置顶提示。
