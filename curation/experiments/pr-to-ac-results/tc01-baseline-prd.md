# AI 中文搜索工具 PRD（Baseline — TC01）

> 生成方式：完整遵循 skills/prd-development/SKILL.md 的 10 节模板 + AC 规则。
> 输入：「我想做一个 AI 搜索工具，像 Perplexity 但更聚焦中文内容」
> 模式：fast-path（用户仅一句话，无发现笔记；Open Questions 机制兜底）

## 1. Executive Summary

中文用户使用 Perplexity 等英文优先的 AI 搜索工具时，答案质量因语言与信源生态而显著降级。本产品为中文互联网构建一个答案优先的 AI 搜索引擎：检索中文信源、以引用支撑生成答案、并保留信源可溯性。若达成，将把中文用户"提问→可信答案"的时间从多轮翻页缩短为一次查询，并建立中文 AI 搜索的信任标准。

- **problem**：中文 AI 搜索的答案质量与信源可信度不足
- **solution**：中文信源优先的 RAG 答案引擎 + 逐句引用
- **impact**：查询到可信答案的时间缩短为一次交互

## 2. Problem Statement

- **谁**：中文重度搜索用户（学生、研究者、内容创作者、职场人士）
- **什么问题**：现有 AI 搜索工具（Perplexity、ChatGPT 搜索）以英文语料为主，中文查询时出现信源失配、答案模板化、引用缺失
- **为什么痛**：中文互联网的优质内容（知乎、微信公众号、专业论坛）未被有效索引；用户被迫回到传统搜索引擎再自行交叉验证
- **证据**：⚠️ Open Question — 缺少一手用户调研数据。已知假设：Perplexity 中文查询的引用命中率显著低于英文（需 A/B 测量，见第 10 节 OQ-2）

## 4. Strategic Context

- **为什么现在**：中文大模型能力已到可用临界点；Perplexity 模式验证了答案优先搜索的需求，但其中文覆盖是明显空档
- **竞争格局**：⚠️ Open Question — 需正式竞品分析（见 OQ-4）：Perplexity（英文优势）、秘塔（中文先行者）、Kimi/豆包（通用助手形态）
- **差异化假设**：逐句引用 + 中文信源质量分级是可防御的信任壁垒

## 5. Solution Overview

一个答案优先的中文 AI 搜索 Web 应用：
1. 查询框 → 生成答案，每个关键论断带 [1][2] 编号引用
2. 侧栏展示信源卡片（域名、标题、可信度标签）
3. 追问式会话，可针对某条引用深挖
4. 中文信源优先的检索排序（专业站点权重高于内容农场）

## 7. User Stories & Requirements

**P0**
- US-1：作为研究者，我想输入中文问题直接获得带引用的答案，以便无需手动交叉验证。
- US-2：作为用户，我想点击引用编号跳到原文出处，以便核查答案可信度。
- US-3：作为用户，当查询无高质量信源时，我想得到明确提示而非编造答案。

**P1**
- US-4：作为创作者，我想追问深挖某条引用的上下文，以便确认数据可靠性。
- US-5：作为用户，我想查看信源卡片上的可信度标签，以便快速判断信源质量。

### Acceptance Criteria

**US-1（答案生成）**
- AC-1.1 Given 用户输入中文问题，When 提交查询，Then 3 秒内开始流式输出答案，且每个事实性论断后带编号引用标记
- AC-1.2 Given 查询命中中文专业信源（如学术站、官方媒体），When 生成答案，Then 引用列表中专业信源排名前列
- AC-1.3 Given 查询触发敏感或低质内容农场，When 生成答案，Then 该信源被降权或排除，答案不引用内容农场作为唯一依据
- AC-1.4 Given 网络中断发生在流式输出中，When 用户重试，Then 已输出部分不丢失，会话可恢复继续

**US-2（引用跳转）**
- AC-2.1 Given 答案含编号引用，When 点击编号，Then 页面滚动到对应信源卡片并高亮原文摘录
- AC-2.2 Given 引用原文已被删除或移动，When 点击跳转，Then 显示缓存快照并标注"原文已不可达"

**US-3（无信源诚实性）**
- AC-3.1 Given 查询无任何高质量信源匹配，When 生成答案，Then 输出"未找到可靠信源"提示并列出已尝试的低置信结果，禁止编造
- AC-3.2 Given 信源质量均低于阈值，When 生成答案，Then 明确标注低置信度警告

**US-4（追问深挖）**
- AC-4.1 Given 答案中某条引用存在，When 用户针对该引用追问，Then 会话上下文聚焦该信源并返回其原文相关段落

**US-5（可信度标签）**
- AC-5.1 Given 信源卡片渲染，When 加载，Then 显示域名、标题与可信度标签（如 官方/专业媒体/社区/未验证）四档之一

> 每条 P0 故事 ≥3 条 AC 且至少 1 条异常态（网络中断/无信源/原文失效）——符合 PRD 规则。

## 8. Out of Scope

- 生成式内容创作（写作助手功能）——不是搜索的 MVP 范围
- 移动原生 App——先验证 Web 需求
- 用户账号体系与历史同步——MVP 用本地会话
- 英文查询优化——专注中文，英文仅自然兼容不专门优化

## 9. Dependencies & Risks

- **技术依赖**：中文检索索引（自建或采购）、大模型 API、信源质量分级模型
- **风险 R1**：中文信源版权与抓取合规性 → 缓解：优先官方 API 与开放协议源；正式法务评审（OQ-3）
- **风险 R2**：引用覆盖率目标（80%）技术上可能不可达 → 缓解：MVP 先以 60% 为底线目标并测量
- **风险 R3**：答案延迟与成本的平衡 → 缓解：流式输出 + 检索层级缓存
