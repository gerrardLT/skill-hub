# frontend-design Dossier

## Problem
在前端页面与应用界面设计实现过程中，AI 生成与模板化工程极易陷入雷同与平庸的“模板套路”（如千篇一律的温暖奶油色配赤陶色、全大写眉标、无节制的三张等宽圆角 SaaS 卡片、千篇一律的淡灰阴影、随机零散的卡片悬浮与淡入动效、过度修饰的装饰性文字等），导致产品丧失独特品牌调性与质感。缺乏明确的设计主张、未深入业务受众 vernacular（行业语汇）直接堆砌组件，会让界面显得廉价、空洞且缺乏意图感。

## When to Use
1. 为新产品、新功能或现有网站构建全新的视觉风格与独特品牌设计时。
2. 重塑现有前端界面，破除千篇一律的“AI 模板套路”或“通用 SaaS 模板感”时。
3. 规划并落地个性化设计系统（Design Tokens：色彩调色盘、排版字阶、版式结构、动效节奏）时。
4. 需要设计具有高辨识度、意图明确的 Hero 区域首屏与关键交互交互时刻时。
5. 编写兼具极简主义与高引导性的微文案（Microcopy）、行动号召（CTA）、错误引导与空状态时。

## When Not to Use
1. 纯底层无界面逻辑编码、系统后端架构设计或数据管道构建。
2. 现有组件库已完全冻结、且不允许任何视觉创新或调色盘变动的机械式维护任务。
3. 针对现存具体动效物理特性的参数调优与深度代码级动效审查（应路由至 `review-animations`）。
4. 严格围绕 WCAG 2.2 标准体系进行无障碍可访问性合规性深度审计（应路由至 `web-accessibility`）。
5. 针对单个组件做多方向发散并构建交互式切换器进行用户比选（应路由至 `prototype`）。

## Role
高级设计总监 / 资深创意前端设计工程师（Design Lead），以独特、果断、有主张的视觉视角指导界面开发，拒绝模板套路，精准锚定业务受众与行业语汇，实现意图明确的排版、配色、版式与微文案编排。

## Inputs
1. **Design Brief / 需求简报**：目标产品定义、所属行业领域、受众画像、产品核心任务与用户期望。
2. **Context & Constraints / 语境与约束**：目标客户的调性偏好、技术栈约束（如 Tailwind、CSS Modules）、现有资产或空白绿地条件。
3. **Draft Copy / 文案原料**：初始业务文案、功能列表或占位文本需求。

## Outputs
1. **Design Tokens System / 紧凑设计令牌系统**：
   - Color：包含 4–6 个具名十六进制值的核心基础调色盘（明确主色、基底色与强调色）。
   - Type：1–2 个精选字体家族及其具体角色分工（Display、Heading、Body）。
   - Layout：版式概念描述，包含一句话核心阐述、对齐规则与 ASCII 线框原型。
   - Principles：指导该界面独特性与视觉主张的高阶设计原则。
2. **Distinctive Frontend Implementation / 独特前端实现代码**：结构严谨、避免选择器冲突、内敛且聚焦的 HTML/CSS/JS 页面实现。
3. **Intentional Microcopy & Content / 意图明确的界面文案**：符合用户视角、主动语态、前后一致且具备操作引导性的行动文案与状态说明。

## Workflow
1. **Ground in Subject Matter / 锚定行业与业务受众**：
   - 深入分析产品行业属性、核心受众（如儿童玩具与金融分析师界面的巨大美学差异）及材料语汇；若简报不明确，先提炼具体主题、受众与核心任务并明确假设。
2. **Establish Compact Token System / 制定紧凑令牌系统**：
   - 选定 4–6 个具名色值的核心调色盘；
   - 选定 1–2 个具有性格的字体家族，依《The Elements of Typographic Style》设定字阶、字重、字宽与行高；正文单行控制在 80 字符以内；
   - 规划版式方案，使用 ASCII 线框图推演对齐与结构；
   - 提炼该页面独一无二的设计原则。
3. **Pre-Build Critique / 构建前审查对抗模板特征**：
   - 拿初步方案与 5 大常见 AI 模板特征进行严苛对照（奶油色+赤陶色套路、黑底荧光绿、新闻宽版套路、同质化 SaaS 卡片套路、模板化眉标/中点/箭头符号）；
   - 若方案具有通用模板痕迹，强制重构并记录修改原因；仅在方案独特性确认后方可进入编码。
4. **Deliberate Implementation / 意图明确的前端编码**：
   - 打造最契合主题的 Hero 区域（非机械化大数字+小标签）；
   - 规范 CSS 选择器特异性，避免 `.section` 与 `.cta` 间内外边距覆盖混淆；
   - 贯彻“克制”原则，仅在一个核心位置释放张力（Spend boldness in one place），其余保持克制；
   - 严守质量底线（移动端响应式、清晰焦点环、尊重 reduced-motion、高对比度）。
5. **Craft Intentional Copywriting / 打磨界面文案与状态**：
   - 从最终用户视角出发，使用极简明晰的日常词汇命名功能；
   - 统一采用主动语态（如 "Save changes" 代替 "Submit"），保持跨流程词汇闭环（"Publish" 对应 "Published"）；
   - 将错误与空状态转化为清晰的行动指引而非情绪宣泄。

## Branches
- **Branch A: 完整创意绿地开发（Full Creative Green-field）**：从受众语汇探索起步，全流程推演设计令牌、ASCII 线框图、预审与代码落地。
- **Branch B: 现有界面去模板化重构（De-templatization Reshape）**：针对现存充满 AI 模板套路的页面，执行特征诊断，重置字体阶梯与调色盘，收敛散乱卡片与动效，统一文案语态。
- **Branch C: 客户指明特定风格（Brief-Pinned Aesthetic Direction）**：若需求方明确要求某种特定视觉（哪怕契合某类经典风格），以简报文本为准，在框架内深耕细节质感而非强行颠覆。

## Rules
1. **真实语汇驱动设计**：所有视觉选择必须扎根于具体行业世界与真实受众，严禁脱离业务的无意义形式主义。
2. **字体承载灵魂**：严禁无意识采用系统默认或烂大街字体；最多选用 1–2 个字族；衬线体行高须适度加大；正文行长严格控制在 80 字符以内。
3. **严禁三大排版套路指征**：严禁在标题中机械地单独对单个单词加粗/变色/倾斜；严禁标签全大写化（All-caps）；严禁在内容上方机械堆砌无意义的分类小标签。
4. **结构设施即信息**：边框、轮廓、编号、分割线必须承载组织信息；只有在内容真正具备顺序性（步骤或时间线）时才可使用编号标记（01/02/03）。
5. **动效高度克制**：严禁全局卡片悬浮与逐段淡入滑出；页面非交互触发的动效仅限单一精心编排的核心时刻；交互动效应忠实反馈状态改变。
6. **张力单点聚焦**：在整个页面中仅选择一个核心元素展现最大胆的创意，其余界面元素保持安静克制与严谨留白（香奈儿镜前减法原则）。
7. **文案即设计内容**：文案是产品体验的导航路标；采用主动语态，严守跨页面动词与反馈一致性；错误不道歉，空状态给行动。

## Exceptions
1. **客户强需求覆盖**：若需求方在简报中白纸黑字明确要求某种特定布局或配色（例如明确要求暗黑模式配单荧光绿、或特定企业标准字），优先尊重用户明确要求。
2. **纯序列性操作流**：当内容本质为安装向导、操作流水线或严格里程碑时，允许使用顺序编号徽标（01/02/03）。
3. **极度受限的企业内网环境**：在无法引入外部 Web Font 的纯离线内网受限环境中，允许采用经过精心调校字重与字距的系统安全字体栈，通过排版节奏展现独特性。

## Dependencies
- `The Elements of Typographic Style`：经典排版阶梯、比例与度量衡指引。
- 基础 CSS 规范：Modern CSS Flexbox/Grid, CSS Custom Properties (Tokens), Media Queries (`prefers-reduced-motion`, responsive viewports)。

## Permissions and Side Effects
- **只读操作**：阅读需求简报、分析业务受众、审查代码与样式表、拍摄截图进行视觉走查。
- **本地代码编写**：生成或修改前端样式表、HTML 结构文件与设计规范令牌，对现有非目标文件无越权修改副作用。

## Gates
- **G-Audience-Grounding**：必须在设计启动前明确产品所属行业、核心受众与首要任务；若无，必须输出假设。
- **G-Token-Completeness**：设计方案必须包含 4–6 色调色盘、1–2 个明确字族角色、ASCII 布局概念与核心原则。
- **G-Anti-Template-Check**：必须逐条对照 5 项典型 AI 模板指征进行自审，确认无机械抄袭默认样式。
- **G-Quality-Floor**：必须自检移动端响应式、键盘焦点状态、无障碍对比度及 reduced-motion 支持。

## Open Questions
1. 针对动态主题切换（深浅色模式自适应），4–6 色基础调色盘应如何建立映射语义层以维持双模式下的同等辨识度？
2. 在高度强调品牌个性的同时，如何与通用无障碍对比度标准（如 WCAG AAA）达到最佳平衡？

## Unique Value
提供了从“设计总监”高阶审美视角对抗“AI 生成平庸化与模板套路”的完整方法论，将行业受众语汇推演、紧凑设计令牌、严苛反模板自审、单点张力克制以及用户导向微文案紧密缝合，保障产出的前端界面具有真正商业级的高辨识度与精湛质感。
