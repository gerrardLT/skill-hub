# Metrics Dashboard Dossier

## Problem
在产品研发与运营过程中，团队经常缺乏清晰的数据指标体系，或沉溺于看似繁荣却无法指导行动的“虚荣指标（Vanity Metrics）”。指标零散无因果关联、缺乏层次结构（大杂烩堆砌）、定义模糊缺少计算公式、缺乏明确告警阈值与复盘节奏，导致数据无法指导团队行为改变，无法在业务滑坡前通过先导指标提前预警。

## When to Use
- 为新产品、新业务模块或既有系统设计端到端的数据指标监控体系与仪表盘时；
- 制定产品 KPI、北极星指标（North Star Metric）与输入驱动杠杆时；
- 对团队现有混乱的数据看板进行系统性审计与治理（基于精益数据分析 Lean Analytics 原则）时；
- 规划产品监控告警、数据源对齐与周期性数据复盘机制时。

## When Not to Use
- 纯基础设施、底层服务器硬件或网络层监控配置（应直接使用云原生运维监控平台）；
- 产品尚未定型、无明确价值主张与初始用户的模糊探索极早期（缺乏有效行为数据，应优先使用定性访谈 `interview-script` 或发现流程 `discovery-process`）；
- 针对偶发单次数据排查或一次性 Ad-hoc SQL 取数任务。

## Role
产品数据架构师 / 资深产品经理（Product Analytics PM），负责统合业务目标、用户核心价值与数据工程能力，构建四层指标架构并设计落地规格。

## Inputs
- **必备参数**：`$ARGUMENTS`（待设计看板的产品名称、业务模块或核心场景）；
- **参考上下文**：已有数据看板截图/配置、用户行为日志与埋点字典、战略目标与 OKR 文档、产品路线图。

## Outputs
- Markdown 格式的产品指标仪表盘规范文档（Dashboard Specification）；
- 核心内容包含：
  1. **四层指标架构**：单北极星指标（North Star）、3-5 个先导输入指标（Input Metrics）、健康护栏指标（Health Metrics）、商业与财务指标（Business Metrics）；
  2. **六字段完备指标字典表**：每个指标具备指标名称、精确计算公式（明确分子/分母/时间窗口）、数据来源、图表呈现形式、目标值、告警阈值；
  3. **分层布局线框图**：符合人眼认知流向的仪表盘布局线框设计（包含趋势与 Sparkline 走势）；
  4. **四级复盘节奏规范**：涵盖日检、周会、月度复盘与季度校准的跨周期追踪机制；
  5. **告警响应标准**：告警阈值、接收对象、触达渠道与响应时限要求；
  6. **工具选型落地建议**：根据团队规模与基础设施提供产品分析、SQL BI 与运维监控选型建议（严格遵循本地 PostHog 适配器封禁规范）。

## Workflow
1. **指标体系分层架构**：确立 1 个核心北极星指标、3-5 个驱动输入指标、若干系统健康护栏指标以及商业财务指标；
2. **六字段严格定义指标**：逐一填写指标表，明确分子、分母、采样时间窗口、数据源头、可视化图表选型、目标数值及告警触发阈值；
3. **设计仪表盘布局流向**：按照从上至下、核心到细分的视觉层级组织看板版面布局；
4. **确立四级复盘节奏**：为日度（运营健康）、周度（输入趋势）、月度（北极星与业务目标）、季度（战略重构）设定固定评审时间表；
5. **制定告警响应机制**：界定异常触发阈值、被通知人/角色、通知渠道（Webhook/邮件/IM）与 SLA 响应时效；
6. **提供技术工具选型建议**：根据组织现有技术栈给出产品分析工具、SQL BI 平台与运维基础设施工具的匹配推荐；
7. **生成并落盘规范文档**：将完整看板规格整理为结构化 Markdown 文档以供数据工程与前端开发团队实施。

## Branches
- **指标属性判定分支**：
  - *虚荣 vs 可行动*：凡无法直接引发团队行为改变的指标判定为虚荣指标，严禁进入核心看板；
  - *定性 vs 定量*：定量回答 WHAT，定性回答 WHY，看板必须配套定性反馈输入渠道；
  - *探索 vs 汇报*：汇报指标保持固定基线，探索指标供下钻分析；
  - *滞后 vs 先导*：北极星指标与业务指标多为滞后指标，输入指标必须为先导指标（提前预测并指导行动）；
- **指标审计优化分支**：现有看板按 Lean Analytics 四原则进行逐项审计（剔除坏指标、重构好指标、深挖单一痛点）；
- **工具选型适配分支**：依据团队是否有自建数仓与 SQL 能力，分支推荐轻量 SaaS 分析平台或沉浸式 BI 工具。

## Rules
- **行为改变黄金法则（The Golden Rule）**：如果一个指标不能改变团队的行为，它就是一个坏指标；
- **好指标四大标准（Lean Analytics Criteria）**：
  1. 易懂（Understandable）：建立团队共同沟通语言；
  2. 可比（Comparative）：跨时间段对比（环比/同比），而非单一孤立快照；
  3. 比率或速率（Ratio or Rate）：使用比率/速率而非单纯绝对数字，更能揭示本质；
  4. 行为驱动（Behavior-changing）：能直接驱动明确的业务或开发调整；
- **北极星指标单一性**：整个看板必须且只能拥有 1 个北极星指标，且该指标必须代表对用户的核心价值传递；
- **先导输入指标数量控制**：输入指标严格限制在 3-5 个，作为直接驱动北极星的可操纵杠杆；
- **定义公式精确性**：指标定义禁止模糊概念，必须严格写明分子、分母及统计时间窗口（如 7 日滑动窗口、日活/月活等）；
- **告警行动导向**：告警必须具备明确响应人和 SLA，避免产生无主告警或告警疲劳；
- **安全不变量约束**：工具推荐保持中立分析；根据工作区全局治理禁令，永久封禁 PostHog 适配器与本地依赖。

## Exceptions
- **冷启动埋点缺失**：在新功能上线初期缺乏完备历史数据或埋点未覆盖时，允许使用近似代理指标（Proxy Metric），但必须在规格中标注埋点补全任务与过渡期；
- **数据源延迟或离线同步**：当核心指标依赖每日/每周离线 ETL 时，必须在看板显著标识数据更新频次与延迟容忍度，不可提供实时告警假象。

## Dependencies
- **上游输入依赖**：产品目标与路线图（`outcome-roadmap`, `prioritization-frameworks`）、需求方案（`prd-development`）；
- **下游消费**：度量复盘（`retro`, `metrics-review`）、AB 实验设计（`craft-experiment-design`）、发版前监控预备（`canary`, `ship`）。

## Permissions and Side Effects
- 只读读取用户提供的需求、OKR 或历史数据看板文档；
- 生成并写入看板规范 Markdown 文档；
- 无线上数据库修改、无写埋点代码副作用。

## Gates
- **单一北极星门禁（Single North Star Gate）**：看板定义中必须且只能有 1 个代表核心用户价值的北极星指标，严禁双北极星；
- **六要素完备性门禁（Six-Field Definition Gate）**：所有选入的指标必须 100% 具备名称、精确计算公式（含分子/分母/时间窗口）、数据源、图表类型、目标值和告警阈值六要素；
- **先导杠杆门禁（Leading Input Metrics Gate）**：输入指标数量必须在 3-5 个之间，且必须经过先导性检验（可提前预测并影响北极星）；
- **告警闭环门禁（Actionable Alert Gate）**：每一个告警规则必须明确责任对象、通知渠道与预期响应时限（SLA）。

## Open Questions
- 当北极星指标上扬但健康护栏指标（如崩溃率或单位经济效益）触碰告警线时，团队的跨职能熔断与调优机制如何通过 dev-loop 自动触发降级或复盘？

## Unique Value
将精益数据分析（Lean Analytics）的四大严苛筛选标准与北极星指标架构深度结合，从方法论源头彻底杜绝“虚荣指标”，为跨职能产研团队打造具备高度因果解释力、可执行性与自动化告警机制的看板中枢。
