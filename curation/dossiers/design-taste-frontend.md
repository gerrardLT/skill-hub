# design-taste-frontend Dossier

## Problem
Frontend code generated by modern language models frequently suffers from repetitive "AI-slop" aesthetic defaults: centered hero headlines floating over dark neon-mesh gradients, three identical card containers in a row, ubiquitous Inter + slate-900 typography, unearned serif fonts (Fraunces / Instrument_Serif) claiming false craft, generic warm beige-and-brass color palettes on luxury consumer briefs, div-based fake screenshots, gratuitous em-dash (`—`) punctuation, and broken mobile layouts that fail basic touch and scroll physics. `design-taste-frontend` provides a rigorous anti-slop engineering methodology for landing pages, portfolios, and website redesigns. It enforces room-reading brief inference, parameter-driven dials, authentic design system mapping, layout diversification, strict visual asset disciplines, and a mechanical pre-flight verification gate to ensure output looks bespoke and production-grade.

## When to Use
- Building marketing landing pages (B2B SaaS, consumer tech, creative agencies, event promotions, open-source projects).
- Crafting developer, designer, or studio portfolios requiring bespoke visual identity and deliberate motion choreography.
- Executing website redesigns where existing brand equity, SEO rankings, and information architecture must be systematically audited and either preserved or overhauled.
- Overriding generic LLM design defaults through precise Dial configuration (`DESIGN_VARIANCE`, `MOTION_INTENSITY`, `VISUAL_DENSITY`).
- Auditing frontend page implementations against strict quality gates before delivery (e.g., zero em-dashes, eyebrow count ceilings, CTA button wrap prevention).

## When Not to Use
- Dense operational dashboards, data-heavy enterprise portals, and administrative cockpit UIs (use Fluent UI, Carbon, or Atlassian directly).
- Complex data tables and spreadsheet matrices requiring virtualization and cell-level editing (use TanStack Table or AG Grid).
- Multi-step wizards, onboarding transactional forms, and authentication funnels.
- In-browser code editors and IDE surfaces (use Monaco or CodeMirror).
- Native mobile interfaces for iOS or Android (use platform HIG or Material Design natively).
- Realtime multi-user collaborative canvas applications (OT, CRDT, live presence).

## Role
Anti-Slop Frontend Design Director and Lead UI Engineer. Specializes in translating nuanced user briefs into production-grade, highly differentiated web interfaces that resist generative AI homogenization.

## Inputs
- **Page Archetype**: Landing page (SaaS, consumer, agency, event), portfolio (developer, designer, studio), redesign (preservation vs. overhaul), or editorial publication.
- **Vibe Vocabulary**: Expressive keywords supplied by the user (minimalist, Linear-style, Awwwards, brutalist, luxury consumer, Apple-like, editorial, dark tech).
- **Reference Signals & Brand Assets**: External URL inspirations, screenshots, existing logos, vector marks, color palettes, and typographic assets.
- **Audience & Contextual Constraints**: Target reader cohort (B2B procurement committee, design-savvy consumers, hiring managers) and regulatory or accessibility constraints (public sector, trust-first, WCAG AA compliance).
- **Three Dials Baseline**: `DESIGN_VARIANCE` (1-10), `MOTION_INTENSITY` (1-10), `VISUAL_DENSITY` (1-10) with standard baseline `8 / 6 / 4`.

## Outputs
- **One-Line Design Read**: Explicit declaration before code generation: `"Reading this as: <page kind> for <audience>, with a <vibe> language, leaning toward <design system or aesthetic family>."`
- **Dial Parameter Contract**: Concrete values for `DESIGN_VARIANCE`, `MOTION_INTENSITY`, and `VISUAL_DENSITY` tailored to the brief.
- **Foundation Selection**: Verified choice of an official design system package (e.g., Fluent, Material 3, Carbon, Primer, GOV.UK, Radix Themes, shadcn/ui) or an honest native CSS/Tailwind aesthetic implementation.
- **Production-Grade Frontend Code**: Modular React/Next.js code adhering to Server Component hygiene, Motion animation best practices, responsive grid architecture, and strict typographic hierarchy.
- **Pre-Flight Verification Audit**: Comprehensive pass/fail checklist covering 50+ mechanical rules before final delivery.

## Workflow
1. **Brief Inference (Read the Room)**:
   - Analyze user prompt across page kind, vibe keywords, reference URLs, target audience, incumbent brand assets, and non-negotiable regulatory constraints.
   - Output the mandatory one-line "Design Read". If the brief is genuinely ambiguous, ask at most one targeted clarifying question; never output multi-question interrogations.
   - Enforce anti-default discipline: explicitly reject AI-purple glows, dark mesh backgrounds, three identical cards, and generic glassmorphism.
2. **Configure the Three Dials**:
   - Derive dial settings from the design read: `DESIGN_VARIANCE` (1=Symmetry to 10=Artsy Chaos), `MOTION_INTENSITY` (1=Static to 10=Cinematic Physics), and `VISUAL_DENSITY` (1=Airy Gallery to 10=Packed Data). Baseline defaults to `8 / 6 / 4`.
3. **Map Brief to Design System or Aesthetic**:
   - If the brief matches an established ecosystem, adopt the official package (e.g., `@fluentui/react-components`, `@carbon/react`, `govuk-frontend`, `@radix-ui/themes`, `shadcn/ui`). Never recreate official frameworks by hand, and enforce strictly one design system per project tree.
   - If the brief is an unowned aesthetic (Bento, Brutalism, Editorial, Liquid Glass), implement via native CSS and Tailwind with honest code documentation.
4. **Enforce Architecture and Default Conventions**:
   - Framework: React/Next.js with Server Components (RSC) by default. Isolate motion, scroll listeners, and pointer physics to leaf Client Components (`'use client'`).
   - State: Never use `useState` for continuous scroll or pointer inputs (use Motion's `useMotionValue` / `useTransform` / `useScroll`).
   - Icons: Use approved vector families (`@phosphor-icons/react`, `hugeicons-react`, `@radix-ui/react-icons`, `@tabler/icons-react`). Never hand-roll SVG icon paths and never use emojis as UI glyphs.
   - Layout: Use `min-h-[100dvh]` (never `h-screen`) for full-height heroes to prevent mobile viewport address bar jumping; use CSS Grid instead of complex flexbox percentage calculations.
5. **Execute Design Engineering Directives (Anti-Slop Rules)**:
   - Typography: Default to modern sans display (Geist, Outfit, Cabinet Grotesk); enforce strict Serif Discipline (ban Fraunces and Instrument_Serif as defaults); reserve leading-[1.1] and padding for italic descenders (`y g j p q`).
   - Color: Limit to one accent color (<80% saturation); ban the AI-purple/lila glow; strictly enforce the Premium-Consumer Palette Ban (prohibit default warm beige/brass hex families `#f5f1ea`, `#b08947`); lock accent color across all page sections.
   - Layout: Enforce Anti-Center Bias when variance > 4; lock corner radii across the entire page (all-sharp, all-soft, or all-pill); hero must fit initial viewport (headline ≤2 lines, subtext ≤20 words/4 lines, top padding max `pt-24`, max 4 text elements); enforce Bento Cell Count Rule (exact count, zero empty tiles); enforce Eyebrow Count Rule (max 1 eyebrow per 3 sections); enforce Split-Header Ban; cap zigzag alternation at max 2 consecutive sections.
   - Visual Assets & Content: Prioritize image-generation tools > real photography (Picsum descriptive seed) > explicit placeholders; strictly ban div-based fake screenshots and fake numbers; enforce Copy Self-Audit; lock single page theme (light, dark, or auto; zero mid-page section theme flipping).
6. **Apply Context-Aware Micro-Interactions**:
   - Implement motion only when motivated (hierarchy, storytelling, feedback, state change). Limit horizontal marquees to at most one per page.
   - Use canonical skeletons for Sticky-Stack (`start: "top top"`, `pin: true`) and Horizontal-Pan. Strictly ban `window.addEventListener("scroll")`.
7. **Execute Redesign Protocol (When Applicable)**:
   - Classify mode into Greenfield, Redesign-Preserve, or Redesign-Overhaul. Perform pre-touch audit (brand tokens, IA, content value, SEO baseline, existing dials).
   - Protect URLs, primary nav labels, form field schemas, brand marks, and legal copy from silent modification.
8. **Final Pre-Flight Gate Check**:
   - Mechanically verify all items in Section 14, especially the zero em-dash (`—`) and en-dash (`–`) rule, CTA button wrap ban, shape/color consistency locks, and eyebrow count thresholds.

## Branches
- **Greenfield Landing / Portfolio**: Executes steps 1 through 6, setting dials to high-variance/high-motion baselines and generating bespoke visual layouts.
- **Redesign - Preserve**: Establishes audit baseline, measures existing dials, preserves existing brand colors (even if purple/beige), retains IA/SEO metadata, and applies surgical modernization (typography, spacing, subtle motion).
- **Redesign - Overhaul**: Keeps underlying content and page hierarchy intact while replacing the visual and component layer with a completely fresh design language.
- **High-Motion Branch (MOTION_INTENSITY > 4)**: Activates GSAP ScrollTrigger or Motion scroll-driven sequences, with mandatory `useReducedMotion()` fallback and strict `useEffect` cleanup.
- **Static / Low-Bandwidth Branch**: Caps motion at dial 1-3, eliminating scroll-hijacks and complex choreography, ensuring pure CSS transitions and zero main-thread overhead.

## Rules
- **Zero Em-Dash Policy (Non-Negotiable)**: The em-dash character (`—`) and en-dash separator (`–`) are completely banned across headlines, eyebrows, pills, body copy, quotes, attributions, buttons, and alt text. Only standard hyphens (`-`) and math minus signs are permitted.
- **Eyebrow Density Ceiling**: Small-caps tracked eyebrow labels (`uppercase tracking`) are capped at a maximum of 1 per 3 sections (ceiling of total sections divided by 3). The hero eyebrow counts as 1; consecutive eyebrows are prohibited.
- **Hero Viewport Fitting**: The hero section must fit entirely within the initial viewport. Headline maximum 2 lines on desktop; subtext maximum 20 words and 4 lines; primary CTA visible without scrolling; top padding capped at `pt-24` (6rem); maximum 4 text elements total in the hero stack.
- **CTA Button Integrity**: Desktop CTA buttons must never wrap text across multiple lines. CTA labels must be concise (1-3 words) and button containers must not artificially constrain width. Duplicate CTA intents on a single page (e.g., "Get in touch" and "Let's talk") are strictly prohibited.
- **Anti-Slop Palette Restrictions**:
  - The default AI purple/lila neon glow is banned.
  - The default warm beige/brass/oxblood/espresso palette (`#f5f1ea`, `#b08947`, `#9a2436`, etc.) is strictly banned for premium-consumer briefs.
  - Exactly one accent color is chosen and locked for the entire page.
- **Serif Discipline**: Serif display typography is strictly banned as a default reach. The default for creative and modern brands is sans-serif display. When serif is legitimately justified by the brief, `Fraunces` and `Instrument_Serif` are banned from default selection.
- **Bento & Layout Repetition Constraints**:
  - A bento grid must have exactly as many cells as there is real content (zero empty tiles).
  - No layout family (e.g., 3-column card row, split-text-image) may appear more than once on a single page.
  - Zigzag alternating image/text splits are capped at a maximum of 2 consecutive sections.
  - Split-headers (giant left headline + floating right explainer) are banned as defaults.
- **Visual Asset Honesty**: Div-based fake screenshots and hand-rolled decorative SVG illustrations are strictly prohibited. Use real image generation, real stock photography with descriptive seeds, or labeled placeholder slots.
- **Scroll Performance**: Direct binding to `window.addEventListener("scroll")` or updating React state via `window.scrollY` is strictly banned.
- **Single Page Theme Lock**: A page must maintain one consistent theme (light, dark, or system). Sandwiched inverted sections are strictly banned.

## Exceptions
- **Explicit User Preference Override**: User prompts that explicitly mandate specific colors (e.g., purple/brass), specific fonts (Inter/Fraunces), or specific layouts override the corresponding anti-default bans.
- **Editorial / Manifesto Hero Exception**: Manifesto and publication announcements where typography itself constitutes the entire visual message may use centered heroes without accompanying photography.
- **Deliberate Theme Switch Device**: When the brief explicitly calls for a dramatic "theme switch on scroll" transition, a single full-page theme inversion is permitted once per page.
- **Reduced Motion Hardware Override**: When `prefers-reduced-motion` is active, all dynamic scroll-hijacking, sticky stacks, and continuous micro-animations must instantly collapse to static layouts.

## Dependencies
- Pairs upstream with `discovery-process` and `product-strategy-session` for product value propositions.
- Integrates with `ui-ux-pro-max` and `impeccable` for design tokens, typography scales, and visual craftsmanship.
- Hands off to `frontend-design`, `prototype`, and `web-accessibility` for technical execution and conformance verification.

## Permissions and Side Effects
- **Read Operations**: Reads project `package.json`, configuration files, and design briefs.
- **Write Operations**: Emits clean, componentized React/Next.js and Tailwind CSS markup. Does not install unauthorized external packages or modify system environments.
- **Side Effects**: Isolated purely to the active project repository; zero external network requests during code generation.

## Gates
- **Design Read Gate**: Code generation must not start until the one-line Design Read and dial configuration are established.
- **Pre-Flight Mechanical Gate**: Delivery is blocked if any item in the Section 14 checklist fails, with zero tolerance for em-dashes, wrapping CTA buttons, duplicated CTA intents, or exceeded eyebrow counts.
- **RSC Isolation Gate**: Components employing scroll listeners, motion values, or pointer physics must have `'use client'` at the top and remain isolated leaf nodes.
- **A11y Contrast Gate**: All text, interactive controls, buttons, and form inputs must pass WCAG AA contrast (4.5:1 for body, 3:1 for large text).
