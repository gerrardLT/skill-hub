# competitive-strategy Dossier

## Problem

`competitive-strategy` 用客户情境而非技术分类识别真实竞争，审计结构性 power、切换成本与 incumbent vulnerability，并在低成本和独特差异化之间形成清晰选择。它反对只复制可见功能、把短期增长误当 durable moat，或忽略组织政治、职业风险与业务规则等隐性壁垒。

## When to Use

- 定义 demand-side competitive set、直接 competitors 与跨市场 comparables。
- 评估 network effects、scale economies、switching costs、counter-positioning、business rules 等结构性防御。
- 选择 cost leadership 或 differentiation，寻找 niche foothold、asymmetry 或 incumbent fault line。
- 分析 incumbent launch、pricing、packaging、feature release 等市场信号。
- 形成 competitive/comparables analysis、wargaming、差异化诊断或 switching-cost vulnerability matrix。

## When Not to Use

- 只要求逐功能复制竞品，而不理解其客户、研究、战略与底层规则。
- 把案例数字当通用门槛、预测或默认 benchmark。
- 要求从未访问外链补充事实，或从同名人物、artifact 反填空 Insight。
- 要求证明某 moat 已成立，却没有客户、成本、价格、行为、组织或市场数据。
- 要求未经授权执行联网研究、AI research、数据共享或外部系统动作。

## Role

执行者帮助用户识别 durable moats、market threats 与 uniquely differentiated products；通过结构化问题和模块化框架区分 evidence 与 hypothesis，但不替用户批准投资、定价、并购、发布或数据共享。

## Inputs

输入可包括：产品消失时客户会采用的替代方案、使用情境、competitor/comparable 列表、产品与商业模式、成本和价格结构、release/pricing/packaging 变化、用户与买方不满、组织政治与迁移流程、业务规则、网络和数据资产、公司独特能力、目标 niche、runway，以及可用的 Auction Insights 或客户研究。缺失证据应追问或保持未知。

## Workflow

### [Curated modular workflow]

以下是策展后的模块菜单，不是来源定义的固定七步。按请求场景选用模块，不要求每次全部执行，也不要求固定顺序：

- **Competition set**：询问“产品消失后客户会用什么”，按 situational context 建立 demand-side rivals；需要正式 competitive/comparables analysis 时，再加入 direct competitors 与 comparables。
- **Durable power**：从 structural-power 或七项 defensibility checklist 开始；需要验真时执行 Benefit + Barrier、CAN'T/WON'T、power progression、business rules 或 true switching costs。
- **B2B replacement**：先核对 baseline utility，再按 buyer/user frustration、迁移阻力、业务规则及新差异维度判断进入路径。
- **Release review**：把 incumbent move 当市场信号，把双方 release 当 chess move；按 solution quality、distribution、pricing/packaging 解释相对变化。
- **Differentiation / niche**：在 low cost 与 differentiation 间明确路径，诊断差异维度，并寻找 strategic advantage、industry primitive、niche foothold 或 incumbent fault line。
- **Research support**：仅在相应输入可用时选择 Auction Insights、quarterly wargaming、AI-assisted research 或 Wayback；工具使用受权限 safeguard 约束。

## Branches

- incumbent 免费化或复制核心价值：记录为市场转折信号，评估是否应聚焦更高杠杆、更可防御部分；不预设必然结果。
- capability 对手做不到：记录 CAN'T 的结构原因；做得到但会伤害既有业务：记录 WON'T / counter-positioning。
- baseline utility 未达标：先 meet the bar；达标后才在新维度 differentiate，顺序不可反转。
- buyer/user 四象限：仅 user 不满 → 难赢，因为 users 不控制预算；仅 buyer 不满 → 只有克服 switching costs 后才有路径；buyer 与 user 都不满 → 最佳机会；buyer 与 user 均未受挫 → don't bother。
- horizontal product：当且仅当特定 audience 面临足够多 use cases 且想用 ONE tool 时可胜过 vertical；若每个 use case 都有定制 vertical 且 buyer 问题不够多，则 vertical 胜出，并保留长期不确定 PMF 风险。
- industry format 已成为用户预期：可采用 primitive；若只是竞品可见 feature，则不机械复制。
- crisis moat-building：仅在同时有足够 runway AND ability 时执行。
- Wayback Machine：仅作为未来条件性 tool-action；产物生成过程未执行。

## Rules

- 按客户情境定义竞争，不按技术类别机械归类。
- durable power 同时需要 material Benefit 与 durable Barrier。
- 低成本和独特差异化应形成明确路径，避免 stuck in the middle。
- 复制 competitor feature 前先理解研究、客户、战略、数据模型与 business rules。
- incumbent move 是 signal，不自动等于立即影响或必然结局。

## Gates

### Source Gates

- **Benefit + Barrier Gate**：Benefit 必须是结构性 lower cost 或 higher price，Barrier 必须是 durable imitation barrier；两者缺一即不通过。
- **Horizontal IF AND ONLY IF Gate**：这是 source-defined Gate：同一 specific audience + 足够多 use cases + ONE-tool demand 三者同时成立，才可通过 horizontal；若每个 use case 都有 tailor-made vertical solution AND buyer 缺少足够多样的问题，则进入 vertical/fail，aggregate TAM 不得作为通过证据。通过后仍须记录 long/uncertain PMF、ambiguous customer rejection、team second-guessing、investor pivot pressure，以及 endurance/defer。

### [Curated acceptance check]

- **Demand-side check**：是否能回答产品消失后客户会用什么。
- **Cost-path choice check**：是否在 low-cost economics 与 premium/unique differentiation 间明确选择，记录 scale/cost economics、premium/unique value，并说明未选路径的理由。
- **Operational-effectiveness check**：是否分别记录 same-race-better、activities-differently、different-activities、copyability 与 chosen race；该 Gate 与 Cost-path choice check 相互独立，不能互相替代。
- **Switching check**：是否覆盖安装成本、政治、情绪、职业、流程、优先级、惰性与生态，并正确使用 buyer/user 四象限。
- **Evidence check**：是否区分本地 quote、本地策展摘要、用户数据、假设与未核验外链。
- **Output check**：仅适用于 competitive/comparables analysis，且来源定义的三组件都需满足：1) head-to-head features/strengths summary + color coding OR heat map；2) focus/investment commentary；3) key feature deconstructs AND screenshots。若因授权或环境限制不能生成 screenshots，则标记 incomplete/defer，不得视为三组件通过；该权限处理是 curated safeguard，不是来源原文。
